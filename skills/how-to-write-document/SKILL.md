# 文档写作规范

## 一、适用范围与组织方式

本 skill 指导六类文档的写作，不负责运行实验、替用户作业务决策或自动生成未知事实。**一种文档类型对应 `types/` 下的一个文件夹**；入口只保存通用要求、选择方式和执行流程，不集中复述各类型的逐节约束。

每个类型文件夹含两件东西：

- `README.md`：该类文档的规范，按以下顺序组织——**整体要求与约束**（目的、读者、证据标准、风格、范围及缺失信息处理）→ **整体结构与模板**（章节序列并指向模板）→ **各部分写作要求**（按模板顺序说明目的、必需内容、表达方法、检查标准与常见错误）→ **交付前检查**。
- `templates/`：保存一种或多种可直接复制的预设模板（文件名按预设区分），含三部分——**空白模板**（占位符版本）、**填写示例**（示意每节应达到的粒度，示例值一律虚构）、**真实示例**（可核查的成品链接；没有就写“暂无”，不编造）。

规范中的“必须”是交付要求，“建议”是默认做法，“条件适用”只在对应场景触发。不能把条件适用内容强行套用到所有文档，也不能把关键内容删掉后用“不适用”掩盖信息缺失。

各部分要求应回答五个问题：**这一节要解决什么问题、必须包含哪些信息、怎样组织和表达、如何判断写完整、哪些写法不可接受**。不能仅重复章节标题或把检查留给读者自行理解。结构模板与逐节要求须按名称和顺序一一对应；头部信息、结论、正文及附录都应有对应要求。

## 二、类型选择

| 文档类型 | 核心任务 | 主要读者 | 默认风格 | 规范 |
|---|---|---|---|---|
| 技术方案 / 设计文档 | 说明技术取舍、实现路径与上线保障 | 技术评审人、实现者、运维与安全相关人员 | 客观工程化，条件和接口精确 | [技术方案](types/technical-design/README.md) |
| PRD | 说明用户需求、范围、行为与验收标准 | 产品、设计、研发、测试 | 规约式、明确、可测试 | [PRD](types/prd/README.md) |
| One Pager（一页纸） | 用一页帮助读者批准、否决或调整一项投入 | 负责人、决策者、资源提供方 | 短句、直接、以请求和收益为中心 | [One Pager](types/one-pager/README.md) |
| 实验报告 | 判断某项改动是否产生效果以及结论可信程度 | 评测、研发、上线决策相关人员 | 数据驱动、审慎、可复现 | [实验报告](types/experiment-report/README.md) |
| 调研报告 | 用调查资料与分析回答研究问题并给出判断 | 业务、产品、技术或采购决策者 | 来源清楚、比较公平、边界明确 | [调研报告](types/research-report/README.md) |
| 论文 | 围绕研究问题提出并验证学术贡献；学位论文还受学校模板与流程约束 | 编辑、审稿人、领域研究者；学位论文另含院系与答辩组 | 学术论证、引用规范、可复核；按期刊选择预设，学位论文按学校模板 | [论文](types/paper/README.md) |

各类文档的模板见对应文件夹的 `templates/`。调研报告也用于用户访谈、竞品和市场分析，不限于技术选型。离线评测属于实验报告的一种数据获取方式，按同一份规范中的适用要求处理。

选择时优先看**主要需要回答的问题**，而不是文档标题中的关键词。一个请求确实包含不同类型的交付物时，分别形成独立文档并相互引用，不把两份完整规范拼成一份长文。无法判断类型时，先确认读者和期望动作，不临时发明未定义类型。论文按研究内容与目标期刊选择预设；学位论文按学校当届模板与院系规定，学校指南优先于本 skill 的风格建议，不能把模板宣称为官方排版或投稿合规证明。

## 三、通用写作要求

### 3.1 先明确任务，再组织内容

- 确定读者、文档用途、要回答的问题、期望动作、范围与交付形式。
- 信息已在对话或资料中明确时直接使用，不重复提问；只有会实质影响写作的缺口才集中询问。
- 不能确认的信息写成“待确认：缺什么、由谁确认、何时需要”。负责人或日期未知时如实标未知，不代用户编排承诺。
- 只保留服务于文档任务的内容。正文给判断与关键依据，附录保存详细原始材料；重要风险和限制不能藏进附录。

### 3.2 结论简练清楚，依据与判断相邻

- 先明确结论、建议或请求，再给得出它的关键依据，最后交代必要边界。
- **实验报告和调研报告必须明确结论及支撑结论的数据。** 数据应给关键对照、变化、分母或样本量、口径以及来源；不是把全部统计表搬进摘要。
- 结论摘要优先采用三句：判断或建议 → 关键数据 → 边界或下一步。三句是压缩方法，不得为满足字数而删除会改变判断的重要信息。
- 质性结论可以引用真实原话、观察记录与证据编号；没有量化依据时说明缺口，不能制造分数、比例或统计显著性。
- 技术方案中的预期效果、PRD中的目标、One Pager中的收益估算，不得冒充已验证结果；明确标注事实、估算、目标或假设。
- 禁止“整体较好”“综合考虑”“各有优劣”代替回答问题。证据不足时直接说无法判断并说明缺什么。

### 3.3 证据真实、可追溯、口径一致

- 数字须有指标定义、单位、统计范围、来源与时间；对比须说明基线和条件。
- 区分百分比与百分点、绝对变化与相对变化、目标与实测、总体与子样本。各章节引用同一组数据时数值和口径必须一致。
- 分清事实、推断与建议；对重要推断标示证据和推导，不把来源的宣传性描述改写成事实。
- 不编造引文、样本、链接、实验配置、置信区间或执行状态。规范中的占位符不是数据；若给虚构格式示例，必须明确标注，实际交付时替换为真实证据或缺口说明。
- 实验报告和调研报告须提供支持重要结论的典型例子，明确其来源、代表性与结论映射；检查反例、失败样本和例外场景。没有发现反例时说明检查范围与限制，不伪造反例。
- 典型例子不能替代总体数据，也不能凭单个例子证明因果或普遍性。

### 3.4 语言、图表与元信息

- 默认中文正文；专有名词可保留英文，缩写首次出现给出解释，全文保持术语一致。
- 英文模板及英文例子的所有语言内容必须使用英文，包括标题、章节、说明、占位符、表头、图注、注释、链接标签和映射指引，不混入中文提示。共享中文规范可保留中文，但英文模板应通过模块编号和语义对应规范，不为名称逐字匹配而使用中文标题。
- 一段一个中心意思，首句优先给判断或要点。标题应可搜索、表达具体主题，标题链应能说明逻辑。
- 用明确的行为、条件和指标替代“适当”“较大”“尽量”“优化体验”等空泛表述；不使用夸张营销词强化证据不足的判断。
- 事实和完成状态使用准确时态。日期写绝对日期，需要具体时刻时带时区；规范模板使用占位符，不把示例日期带入交付稿。
- 图表须有标题、单位、口径、来源和必要说明；图中重点在正文中解释。不要把截图作为唯一可阅读的证据。
- 文档头部写清标题、类型、版本或更新时间、状态、作者或责任人、读者以及重要关联材料。短文档可压缩成一行，不为元信息占用过多正文。
- 按资料敏感度脱敏，不泄露账号密钥或无关个人信息；脱敏后的证据须仍能通过授权渠道核查。

## 四、执行流程

1. **定位**：读取用户材料，明确类型、读者和主要问题，记录必要缺口。
2. **加载规范**：读取该类型的 `README.md`，再打开 `templates/` 下模板。先看整体要求，再看填写示例，最后按逐节要求写，不只截取模板而忽略约束。
3. **建立结构**：列标题及每节需要的数据、证据或待确认信息；用户要求先看大纲时，在正文写作前交付大纲。
4. **完成正文**：按逐节规范组织内容。先整理证据与分析，再撰写最终结论。报告与决策文档默认结论在前；论文摘要概括主要发现，正文按目标期刊的学术论证顺序，不强行前置结论章节。
5. **核对全文**：检查结构覆盖、数字一致、证据追溯、边界、典型例子与可执行下一步。
6. **压缩与交付**：删重复和过程性流水账。原始材料移至附录，保留关键依据；说明仍未解决的阻塞，不把草稿称为已定稿。

## 五、交付检查

- [ ] 选择的类型、读者和主要问题一致，未拼接不同类型的完整模板。
- [ ] 整体结构的每个重要部分有实质内容；条件适用部分的采用或省略有依据。
- [ ] 结论清楚、简短，支撑数据或证据就在结论附近，重要限制未被省略。
- [ ] 事实、估算、目标、推断与建议没有混淆，缺失信息未被虚构补齐。
- [ ] 摘要、正文、图表和例子之间的数字、口径、结论一致。
- [ ] 实验报告与调研报告的典型例子可核查，代表性、反例检查和边界明确。
- [ ] 每条重要需求、目标、结论或建议有对应验收、证据或行动。
- [ ] 责任人、期限与承诺有真实依据；未知项如实标示。
- [ ] 类型文件末尾的交付前检查已完成；格式、链接、权限和脱敏符合交付需求。

## 六、交付格式与其他能力

本 skill 负责内容与结构。用户另要求 Word、PowerPoint 或 Excel 成品时，按实际交付格式加载对应 Office skill；不因文档中提到一种格式就擅自新增交付物。

规范不要求任何特定实验流水线或业务工具。已有评测结果、访谈记录或外部资料可作为输入，但仍须核对来源、方法和适用范围。不要将工具名称当成证据质量保证。

[类型目录索引](types/INDEX.md) 汇总目录结构、文件职责与阅读顺序。修改本 skill 时，同步入口、索引、类型 README 与其模板，保持模板小节与 README 逐节要求一一对应。
