# 技术选型报告写作规范

## 一、整体要求与约束

- **用途（必须）**：回答“在给定约束下选哪个、为什么、在什么条件下成立”，并让不同意的人能按同一组指标复核结论。适用于框架、数据库、中间件、云服务、供应商、架构路线等多候选项的决策；不适用于无候选的实施细节（用[技术方案](../technical-design/README.md)），也不适用于只罗列资料的综述（用[调研报告](../research-report/README.md)）。
- **读者（必须）**：决策者先读结论、代价与前提；评审者按维度、实验记录与原始数据复核；实施者看迁移与回滚。写明决策时点、决策人和本次需要谁批准；决策人未知时标待确认，不代替其签字。
- **证据（必须）**：优先可复现的实测；其次是公开基准、供应商数据与同类案例，但必须标注来源、版本、环境、采样时间与利益关系。供应商的宣传值不能写成实测；不得编造实验数据、样本量、置信区间或“内部压测”结果。
- **结论与前提绑定（必须）**：结论必须写明适用前提——版本、部署形态、负载与数据规模、预算与合规条件。前提变化时给出复评触发条件；没有前提的“最优”不成立。
- **篇幅与取舍（必须）**：主文只保留决策所需内容；原始数据、脚本、完整对比表、日志放附录，但关键反例、失败结果和不可比项不能只出现在附录。
- **风格（必须）**：客观工程化，用“在什么条件下，哪个选项，测到什么值，因此选它”表达；区分事实、估算、假设与建议。禁止“综合来看”“各有优劣”“业界主流所以选它”等无依据表述。
- **缺失信息（必须）**：未做的实验、未确认的预算、许可、合规结论、未知责任人与时间，统一标“待确认”，并说明对结论的影响；不得用“预计”“大概”填补实验缺口。
- **规范强度**：“必须”为交付底线；“建议”可按场景调整并保留理由；“条件适用”须判断触发条件，不适用时说明原因。

## 二、整体结构与模板

章节按下列顺序组织，顺序固定；不适用的小节说明原因后省略，不删除整段证据链。

0. 文档信息
1. 结论与决定
2. 选型问题、约束与范围
3. 评估维度与指标
4. 候选方案
5. 实验方法与执行
6. 实验结果
7. 比较、决策与敏感性
8. 风险、局限与复评条件
9. 落地建议与后续
10. 附录与来源

完整可复制模板见 [templates/technical-selection.md](templates/technical-selection.md)，内含空白模板、填写示例、真实示例链接。写作时先取模板，再回到本文「三、各部分写作要求」逐节核对；模板小节与本文一一对应。

## 三、各部分写作要求

### 0. 文档信息

- **目的**：让读者确认依据的是哪一版材料、结论处于什么决策状态。
- **必须写什么**：标题（选型对象 + 时间窗）、选型对象与范围一句话、文档状态（调研中 / 实验中 / 已有结论待评审 / 已批准）、版本与变更摘要、作者与评审方、更新日期、决策人与决策会议（已知时）、关联材料（实验报告编号、预算单、许可意见）。
- **表达要求**：短字段列表；文档状态与决策状态分开写——“实验完成、结论待评审”不等于“已批准”。
- **如何检查**：读者能判断结论是否已生效、引用的实验与预算是否为同一版本。
- **常见错误**：草案标成已决定；更新日期缺失；引用未定稿的实验报告或未确认的预算。

### 1. 结论与决定

- **目的**：一段话回答“选哪个”，并让读者知道代价与前提。
- **必须写什么**：推荐选项与版本；3–5 条关键理由，每条对应第 3 节的指标和第 6 节的数值；主要不选另一强候选的理由；成立前提与主要代价（成本、迁移、供应商锁定、团队学习）；决策状态与下一步；若结论是“暂缓”“分阶段验证”或“维持现状”，同样给出依据与复审时间。
- **表达要求**：推荐三句——“选什么 → 关键数据 → 前提与代价”。可附一屏决策矩阵摘要，但不得用表格代替理由。
- **如何检查**：结论能由第 3、6、7 节推出；读者读完能复述“为什么不是另一个”；结论强度与证据强度一致。
- **常见错误**：“综合最优”没有判据；只给排名不给差距；把未做的实验写成已验证；结论与第 7 节矩阵矛盾；隐去迁移或退出成本。

### 2. 选型问题、约束与范围

- **目的**：定义问题与边界，防止事后追加或放宽约束。
- **必须写什么**：要解决的业务或工程问题及其量化目标；硬约束（预算、许可与合规、现有技术栈兼容、上线时间、团队技能、采购流程）及其来源与是否可协商；非目标与边界；范围（版本、部署形态、数据规模、地区、时间窗）；决策时点与不决策的后果。
- **表达要求**：约束表（约束 / 来源 / 可协商性 / 验证方式）；硬约束与偏好分开。
- **如何检查**：所有候选能用同一组约束筛选；排除项有理由；目标可被第 3 节指标覆盖。
- **常见错误**：把偏好写成硬约束；范围无边界的“全面评估”；决策时点缺失导致结论无法落地。

### 3. 评估维度与指标

- **目的**：把“好不好”变成可测量、可复算的指标，并说明为什么这些维度重要。
- **必须写什么**：每个维度给出——为什么重要（对应第 2 节的目标或风险）；指标名称、单位、方向（越大越好 / 越小越好）；**计算方法**（公式、分子与分母、统计量如均值 / P95 / 固定窗口 QPS、采样窗口、样本量）；数据来源（自测 / 公开基准 / 文档 / 访谈）；判定方式——硬门槛（必须满足的阈值）或排序权重（仅加权评分时）；主观维度的量表、评分者与评分一致性检验。
- **表达要求**：维度表；硬门槛与排序维度分列；权重给来源、设定人和设定时间；不可量化的维度说明用何种证据替代。
- **如何检查**：第三方能按描述复算指标；指标覆盖目标与主要风险；没有“易用性”这类只有名字没有量表的指标。
- **常见错误**：指标无定义只给名字；把不同量纲直接相加；权重临时拍定且不披露；用单一指标代替全部结论；把主观评分包装成客观测量。

### 4. 候选方案

- **目的**：列全可行选项，并说明纳入与排除的理由。
- **必须写什么**：每个候选的名称、版本、部署形态、许可与成本模式、适用前提、纳入理由；被排除的候选及排除依据（不满足硬门槛 / 不可行 / 证据不足）；“维持现状”若可行应作为候选之一；同一产品的不同版本或托管形态分开列。
- **表达要求**：候选表（编号 / 选项与版本 / 形态 / 适用前提 / 纳入或排除理由）。
- **如何检查**：排除理由可核验；“维持现状”的代价被公平计算；没有为衬托推荐项而设的“稻草人”候选。
- **常见错误**：只列推荐项；把不同版本混为一项；隐去许可限制或最低消费；排除理由只有“社区不活跃”而无证据。

### 5. 实验方法与执行

- **目的**：让结果可复现、可比较，而不是一次性演示。
- **必须写什么**：环境（机器规格、操作系统、运行时与依赖版本、网络）；被测配置与关键参数；数据集或负载生成方式、规模与分布；对照组与变量控制；预热、重复次数、随机化或顺序安排；采集工具、统计方法与显著性处理；执行命令或脚本位置；公平性说明（同机、同负载、同数据、同调参投入）。
- **表达要求**：实验记录表（编号 / 目的 / 环境与版本 / 负载与数据 / 对照组 / 重复次数 / 采集指标 / 执行入口）；无法实测的维度写替代证据与局限。
- **如何检查**：他人能按记录复现；第 3 节的每个指标都有对应实验或明确说明为何无法实测；对照组条件一致。
- **常见错误**：不同环境下的数字直接比较；只跑一次就下结论；隐去调参过程；拿厂商基准冒充自测；为推荐项多跑几轮取最好值。

### 6. 实验结果

- **目的**：给出支持决策的原始结果及其不确定性。
- **必须写什么**：每个指标的结果（均值、P95、区间或标准差、样本量）；单位与口径；差异的绝对值与相对值；异常、失败、超时与未达标结果；不可比项及原因；图表（标题、单位、口径、来源）；完整数据放附录或可核查链接。
- **表达要求**：结果表 + 关键图；同一实验的多个指标放在一起；对反直觉结果给出解释或标注“原因未查明”。
- **如何检查**：结果与第 5 节方法一致；异常样本未被删除；结论方向能从数据直接读出。
- **常见错误**：只报最好的一次；删掉失败样本；把估算或推算写成实测；图表缺单位与样本量；用百分比掩盖基数。

### 7. 比较、决策与敏感性

- **目的**：把结果转成决定，并说明这个决定稳不稳。
- **必须写什么**：硬门槛过滤结果（谁被排除、因哪条门槛）；排序或加权得分及权重来源；关键差距及其实际意义（例如 18 ms 是否影响 SLO）；敏感性分析（权重上下调、负载或规模变化、版本差异、成本假设变化）；反例与不适用场景；最终决定与理由；什么条件变化会改选。
- **表达要求**：决策矩阵 + 敏感性表；每行结论指向第 6 节数据。
- **如何检查**：结论能由矩阵推出；敏感性不改变结论时说明稳健范围，改变结论时写清条件；被淘汰项有明确原因。
- **常见错误**：先有结论再凑权重；只给“A 更优”不给差距；忽略成本、迁移与锁定；把加权总分当成唯一依据。

### 8. 风险、局限与复评条件

- **目的**：说明结论的适用边界，避免被当成永久结论。
- **必须写什么**：未测场景与未覆盖负载；版本漂移、维护活跃度与路线图风险；供应商锁定与退出成本；许可、合规与数据出境限制；团队学习与运维成本；复评触发条件（版本、规模、价格、法规变化）与复评时点。
- **表达要求**：风险表（风险 / 影响 / 触发条件 / 缓解或接受理由 / 责任方待确认）。
- **如何检查**：主要风险有缓解措施或明确的接受理由；复评条件可观测。
- **常见错误**：只写“风险可控”；隐去锁定与迁移成本；把未验证的路线图当承诺。

### 9. 落地建议与后续

- **目的**：把决定变成可执行、可回退的动作。
- **必须写什么**：试点或灰度范围与验证指标；迁移路径、数据兼容与回滚方案；采购、许可与安全评审动作；仍需确认的决策；时间与责任人（未知标待确认）。
- **表达要求**：阶段表（阶段 / 动作 / 完成条件 / 责任方 / 时间或待确认）。
- **如何检查**：每步有可核验的完成条件；回滚可执行；验证指标能回答“选对了吗”。
- **常见错误**：把意向写成承诺；没有验证指标；只写“逐步迁移”而无批次与停止条件。

### 10. 附录与来源

- **目的**：保留可复核的原始材料，不打断主文。
- **必须写什么**：来源索引（类型 / 版本 / 发布日期 / 访问日期 / 用途 / 利益关系）；实验脚本、配置与原始数据；完整评分表；术语表。
- **表达要求**：编号与正文引用一致；链接失效时说明替代材料。
- **如何检查**：每个关键数字都能回到某个来源或实验记录。
- **常见错误**：无来源；只给厂商官网首页；来源与正文版本不一致。

## 四、交付前检查

- [ ] 结论在第 1 节，且能由第 3、6、7 节推出；前提与代价写清，结论状态与文档状态一致。
- [ ] 每个指标有定义、单位、方向、计算方法、来源；硬门槛与排序权重分开。
- [ ] 候选包含“维持现状”（如可行）与被排除项，排除理由可核验。
- [ ] 实验可复现：环境、配置、负载、对照、重复次数、统计方法、执行入口齐全。
- [ ] 结果是原始数据与样本量，不是结论；异常、失败与不可比项保留。
- [ ] 决策矩阵与敏感性支持结论；写清“换什么条件会改选”。
- [ ] 风险、锁定、合规与复评条件完整，未测场景已声明。
- [ ] 模板占位符全部替换；虚构示例与估算没有被当作实测结果。
