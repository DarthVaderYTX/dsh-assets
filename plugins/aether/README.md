# Aether

Aether 是 dsh 的左侧栏插件：一个**有向无环图（DAG）任务执行管理器**。它把「可复用的模块」和「实验里的模块使用」分开管理：实验是一张用端口连线搭出的 DAG，运行实验后由执行器按拓扑序并发执行，并把每个节点的状态、日志与产物留在磁盘上。

执行被显式分成「执行环境 → 执行器」两层：模块声明它需要哪个执行环境，宿主把计划节点解析成 placement 后交给对应执行器。当前只内置本机执行器，但模块、实验、运行记录和 API 都已经按“服务器按环境选择执行位置”的形态落地（见「执行环境与远程调度」）。

面板有三个页签：

| 页签 | 作用 |
| --- | --- |
| 实例 | 每个实例是实验 DAG 的一次提交：详情页用实例 DAG 画布呈现，按状态着色，可平移缩放、拖拽节点、点开节点日志，并支持取消 / 重跑 / 删除。实例列表支持按实例名称、实验名、模块 / 节点名、状态或实例 id 搜索。 |
| 实验 | 实验（DAG 定义）的列表与画布编辑器：列表卡片只显示名称与 UUID id（实验本身没有状态），点击卡片进入编辑器；编辑器右侧栏搜索并添加模块 / 子图 / 数据集，画布可平移缩放、端口连线、框选，支持上下 / 左右两种布局。实验编辑器支持多标签：打开子图会新开一个编辑标签，父实验标签保留。 |
| 资源 | 命令模块、数据集模块与已有子图资源的只读详情，含搜索、类型筛选、版本、输入 / 输出端口、默认参数、执行环境；资源创建后不可修改。 |

顶栏有**插件语言**选择（自动 / 中文 / English），只影响 Aether 自己的界面，不修改 dsh 的全局语言。

> 术语：界面上的「实验」是 DAG 定义（内部仍叫 `graph`，API 路径也是 `/graphs`）；界面上的「实例」（英文 instance）是一次提交（内部与 API 仍叫 `experiment` / run）。这样历史数据与旧 API 不需要迁移。

## 概念

- **id**：模块（含子图模块、数据集）与实验 / 子图在创建时都会自动分配一个全局唯一的 UUID id；名称可随时改，id 不变，子图模块的 `graphId`、节点 `moduleId` 与运行记录都引用它。新建时不再手填 id。
- **模块（module）**：可复用的执行单元。
  - `command`：一段通过 shell 执行的命令，可带默认参数与超时。
  - `graph`：指向另一个实验的**子图模块**；被用作节点时，那个实验会内联进当前实验执行。
  - `dataset`：**数据集模块**，只保存 URI / 路径与可选格式；只有输出端口，作为节点执行时把数据集指针写给下游，不启动命令。
  - 每个模块有 `inputs` / `outputs` 两个端口列表（可为空），决定它能否作为连线的起点或终点；输入端口可以标记为**必填**，必填端口没有连线时实验校验不通过。也带 `environmentId`（执行环境）和默认参数 `params`。
- **模块使用（node）**：实验画布上的一个模块实例，引用一个模块，可覆盖参数、改显示名称、拖动位置；节点继承模块的端口与执行环境。连线记录 `fromPort → toPort`。
- **实验（experiment，内部 `graph`）**：模块使用 + 有向连线；必须无环。实验可以被运行，也可以被别的实验当作子图嵌套（引用关系同样必须无环）。
- **实例（instance，内部与 API `experiment`）**：实验提交一次产生的记录，只有实例带运行状态；实验本身没有状态。每个实例在提交后分配一个全局唯一的 UUID id（hash 字符串），实例详情里以 `id=…` 显示，运行目录也是 `runs/<id>`。实例状态由执行单元决定：任一单元失败即**失败**（即使还有单元在跑），全部单元成功即**成功**，执行中即**运行中**，用户取消即**已取消**。提交时会快照当次的模块命令、参数、端口、模块版本与每个节点的执行环境，之后改实验不影响这个实例。
- **子图**：只要被任一 `graph` 模块引用，对应的实验就是子图。子图不能单独运行（运行对话框不列出，API 也会拒绝），但可以在实验编辑器里像普通实验一样打开、编辑、保存；保存会直接更新原实验，引用它的父实验立即使用新定义。子图可以继续包含子图模块，引用链同样禁止成环。
- **编辑标签**：实验 / 子图编辑器支持多标签。打开父实验后，点击子图节点详情里的「在新标签页打开子图」会新开一个编辑标签而不关闭父实验；标签可切换、关闭（有未保存修改时会确认），保存后标签保留。

## 模块库

- 「新建资源」弹窗先通过 radio 选择**模块 / 数据集**，再按类型动态显示基础配置：模块需填名称、描述、文件或文件夹（命令可选），并通过三张独立卡片配置**输入 / 输出 / 参数**——每张卡片可用 `+` 添加、`−` 删除，每行填写名称并用下拉框选择类型；数据集需填名称、描述、URI / 路径与可选格式。确认后进入资源表单补齐必填输入、参数默认值与环境并保存；保存即创建。子图资源不再从资源页新建，已有子图资源以只读详情展示。
- 模块页顶部有搜索框与「全部 / 模块 / 数据集」筛选，匹配名称、描述、端口、数据集 URI 或子图实验名；结果卡片显示名称、描述、版本与 UUID id，右键卡片（或聚焦后按菜单键 / Shift+F10）弹出「复制 id / 详情 / 删除资源」菜单，复制 id 写入剪贴板，删除前需要二次确认。
- **资源创建后不可修改**：保存后即固定，名称、描述、类型、文件、命令、环境、端口、默认参数都不能再改，需要调整请删除后重新创建。资源详情页只读，只保留「返回」；卡片显示 `vN`，新建资源固定为 v1（旧数据可能带历史版本，详情页只读展示）。
- 资源详情页按类型只显示各自属性：模块显示文件、命令模板、输入/输出、参数和执行环境；数据集只显示数据集 URI/格式与输出；子图只显示引用的实验、端口与参数。详情页顶部显示资源 ID（创建时分配、与名称无关的 UUID / hash 形态字符串）。模块的所有配置（名称、描述、环境、端口、文件 / 命令、默认参数）都放在同一张卡片里，默认参数在卡片底部用一条分隔线隔开。资源类型本身只读。
- 每个模块按类别在 `<workspace>/resources/modules|subgraphs|datasets/<module>/` 下独立管理：`resource.json` 描述文件是必备文件，`files/` 放提交的文件/目录，`versions/vN.json` 保存历史版本。现有旧的 `state.json` 模块会在加载时自动迁移到对应类别目录；`state.json` 保留索引镜像。
- 每张图也有自己的目录：可独立运行的实验在 `<workspace>/experiments/<experiment>/experiment.json`，被图模块引用的子图在 `<workspace>/subgraphs/<subgraph>/subgraph.json`。
- 运行时每个节点会记录当时使用的 `moduleVersion`，运行画布与节点详情会显示对应版本。
- 新建**命令模块**时必须提交一个文件或目录：上传时先到隐藏暂存区 `resources/.uploads/<assetId>/`，保存后移动到资源自己的 `files/`，这个 `files/` 就是模块根目录；创建后文件不可替换或移除。上传**文件夹**时只保留文件夹里的内容（文件夹本身不会多套一层），所有文件直接落在模块根目录下。执行时会把模块根目录里的文件复制到该节点的执行文件夹，再在执行文件夹里运行命令。命令留空时，执行器会尝试按扩展名或 `run.sh` / `main.py` / `index.js` 等入口自动执行复制过来的内容，并通过 `AETHER_MODULE_ASSET`、`AETHER_MODULE_FILE` 等环境变量暴露给命令。
- 模块由四部分组成：**上传的文件/文件夹**、**命令模板**、**输入/输出端口**、**参数**。输入、输出、参数都是可选的，也都可以有多个；每个输入/输出/参数都有自己的类型（文本 / 数字 / 布尔 / JSON / 文件 / 目录，参数不含文件与目录）。
- 命令模板使用 `@@名称@@` 引用输入、输出或参数，名称必须已经在三处之一预先定义；保存前会校验占位符是否闭合、名称是否重复或未定义。校验不通过不会保存。兼容旧的 `{{名称}}` 写法，加载时会自动迁移为 `@@名称@@`。
- 输入端口旁有「必填」复选框：勾选后该输入必须在实验里连线，未勾选为可选；重命名/删除端口会同步维护必填列表。参数值是模块默认值，实验中每个节点可以单独覆盖。
- **文件 / 目录输出**：模块运行结束前在 `$AETHER_NODE_DIR/aether-outputs.json` 写输出清单，即可把某个输出端口映射到真实文件或目录：

```json
{
  "report_file": { "path": "report.md" },
  "report_dir": { "path": "artifacts" }
}
```

  `path` 相对节点目录，不能越界；执行器会在运行记录里保存端口、类型（file/directory）与大小。

## 画布

- **实验列表**：实验页只列出名称与 UUID id（实验本身没有状态），点击卡片进入编辑器；「编辑 / 删除」入口在编辑器工具栏里。执行情况与状态看「实例」页：每个实例对应一次提交。实例页只用于查看、取消、重跑和删除，**不再提供新建实例入口**。
- **提交当前编辑**：编辑器工具栏的「提交实验」直接按**当前编辑内容**运行，即使有未保存修改也会生效；但不会写回实验定义，只有点「保存」才永久改变实验。未保存的新实验（没有 id）也可以直接提交，实例会保存这次草稿的快照，重跑仍使用该快照。提交后**停留在实验编辑器**，不会跳到实例页；切换到其它 tab 再切回来时保留正在编辑的实验、草稿、画布视口和选中项（已经在实验页时再点一次「实验」才回到实验列表）。
- **节点信息**：节点卡片按优先级显示名称、`id=<UUID>`、以及合并后的参数（每个 `key=value` 独占一行）。空间不足时文字用省略号或直接隐藏，优先保证名称；节点越高显示的行数越多，把节点拖大后会逐步显示 id 和更多参数，悬停卡片可看完整内容。默认节点尺寸保持紧凑。
- **调整大小**：选中单个节点后四角出现小方块手柄，拖动任一角即可改变节点宽高（最小 160×80）；实验画布里会随实验保存，实例画布里只影响当前查看；取消选中后手柄隐藏。
- **布局方向**：画布工具条的「上下 / 左右」切换 DAG 方向，默认 **上下**；切换时会按新方向重新自动排版并适配视图。端口随方向显示在节点的上/下或左/右边缘，数量与名称来自模块定义。
- **添加模块**：编辑器右侧栏提供搜索框与「全部 / 模块 / 子图 / 数据集」筛选，按名称、描述、端口名、数据集 URI、子图实验名检索；结果可以直接**拖到画布上的任意位置**，也可以单击添加到视口中心。
- **数据集**：数据集模块只有输出端点（创建时不能添加输入），用于连到下游模块的输入；新建时可以选择**直接编辑内容**或**从文件导入**，目前只支持 JSONL / CSV，数据文件保存到 `resources/datasets/<id>/files/`，`datasetUri` 指向该文件。数据集固定一个输出，名称默认 `output`、可由用户修改，并选择其类型；模块和子图按创建时配置的输入 / 输出端点显示，数据集节点在实验画布与运行画布上都以蓝色 `#1D4ED8` 为底色（按 38% 与背景混合），且运行画布不显示其执行状态。
- **端口类型**：实验连线会校验输出与输入类型。类型相同可直接连接；`number` / `boolean` / `json` 可以连接到 `string`；`file` / `directory` 只能连接同类型。不匹配的连线会被拒绝并提示原因。
- **参数**：点击画布上的模块或子图，右侧详情顶部会显示模块名称、类型、执行环境、端口和当前参数；下方可以继续编辑参数（继承模块默认值，节点处覆盖）。节点卡片会直接显示合并后的参数键值（最多两个，其余用 `+N`，悬停可看完整列表）；必填输入端口带 `*` 和加粗端点。
- **平移**：在空白处按住左键（或中键）拖动。
- **缩放**：滚轮围绕指针缩放；右上角有 `−` / 百分比 / `+`，点百分比恢复 100%。
- **连线**：从任一端口拖到另一个模块的对侧端口即可建立连线（正向、反向都行）；没有输入或输出的模块不会显示对应端点，也不能被连到那一侧。**会形成环的连线会被立即取消并提示**，已有环的实验会显示错误并禁用保存与提交；服务端保存或提交时还会再校验一次作为兜底。
- **框选**：按住 `Shift` 再按右键拖动，框选模块与连线（连线按路径中点判断）。
- **删除**：选中后按 `Delete` / `Backspace`，或点画布工具条的「删除选中」；`Esc` 清除选择。
- **整理 / 复位**：`整理` 重新计算自动布局；`复位` 重新布局并适配视图、清除选择。节点被手动拖动后的坐标会随实验保存。
- **分栏调节**：画布与右侧栏之间、右侧栏的「添加模块」与「详情 / 参数」之间各有一条可拖拽分隔条，可以自由调整画布宽度和右侧两部分的高度占比；设置保存在浏览器本地，下次打开保持。
- 画布、运行列表与右侧栏都按可用空间铺开，不再限制在固定宽度/高度内。

端口只是画布与提交契约的一部分；执行时上游仍然通过 `inputs.json` / `outputs/<node>.out` 提供数据（见下节）。

## 运行画布

运行详情不再用表格列节点，而是把这次运行展开后的实例画成一张 DAG：

- 节点按状态着色：**完成 = 绿色 `#22C55E`**、**执行中 = 黄色 `#FACC15`**（带脉冲点）、**失败 = 红色 `#EF4444`**、**未开始 = 灰色 `#9CA3AF`**；背景/边框/状态标签统一使用 40% 半透明色，节点四边使用同样的细边框；跳过 / 已取消也按灰色呈现，节点副标题会写实际状态。
- 支持平移、滚轮缩放、拖拽节点重新摆放；`整理` 回到自动布局，`复位` 自动布局并适配视图。
- 点击节点弹出底部信息条，显示状态、耗时、退出码与错误，并提供「日志」按钮打开该节点的 stdout / stderr。
- **输出端点**：右键已完成模块 / 子图或数据集的输出端点，可「查看输出结果」或「下载输出内容」（左键不再打开菜单）；菜单会跟随端口，拖动节点或平移 / 缩放画布后仍贴着该端点，单击画布空白处关闭。
  - 若端口映射了真实文件：弹窗直接显示文件内容（二进制/超大文件给出提示），可下载原文件；
  - 若端口映射了目录：弹窗列出目录内容，可进入子目录或查看文件，下载按钮把整个目录打包为 ZIP；
  - 未配置映射时回退为节点 stdout。查看/下载通过 `/experiments/artifact` 与 `/experiments/artifact/download`。
- 运行详情提供「复制」：把这次运行对应的实验定义复制成一张新实验草稿并自动进入实验编辑器；如果原实验已删除，则按运行实例的节点与连线重建草稿。草稿没有实验 id，保存时会**创建一张新实验**，不会修改原实验。运行中的实验也可以复制；「取消」只在运行时出现。
- 运行记录会快照提交时的布局方向（`layout`）与展开后的**端口级节点连线**（`edges`，同一对节点之间的多条不同端口连线也会保留），所以即使之后改了实验定义，这个实例的 DAG 仍然稳定。

整体配色也做了收敛：插件强调色混入灰蓝、卡片与画布边框降低对比、阴影变浅，状态色统一使用柔和的绿 / 黄 / 红 / 灰。

## 执行语义

1. 运行时把实验展开成计划：子图递归内联，节点路径用 `/` 表示层级（如 `pipeline/prepare`）；节点的依赖换成上游节点的实际路径。
2. 按节点的 `environmentId` 解析执行环境 → 执行器，把 placement 写进运行记录；当前只有 `local` 可用，需要未注册执行器的节点会在提交时被拒绝。
3. 依赖全部成功的节点才进入就绪队列，最多同时跑「并发上限」个（1–8）。
4. 节点开始执行前，把它对应执行单元（命令模块）的 `files/` 内容复制到执行文件夹 `runs/<run>/nodes/<node>/`；然后按输入端口准备 `input/`：
   - `file` / `directory` 类型：把上游的实际产物复制成 `input/<端口名>`（`dataset` 节点没有执行产物，直接复制它的数据文件）；
   - 其他类型：把上游文本写进 `input/<端口名>`；
   - 没有连线的可选输入写空文件。
5. 命令在**执行文件夹**里运行：等价于先 `cd` 到该节点目录，再执行渲染好的命令模板。`@@输入名@@` 对 file/directory 类型替换为 `input/<端口名>` 的绝对路径，其他类型仍然替换为上游文本；`@@输出名@@` 替换为执行文件夹里的输出文件路径。
6. `dataset` 节点不启动命令：把 `{ kind, name, uri, format, params }` 写到 stdout，下游从 `inputs.json` 读取。
7. 节点失败后，它的下游标记为 `skipped`，其他分支继续执行；运行最终状态为 `failed`。
8. 取消会结束整个进程树，正在运行的节点标记 `cancelled`，未开始的节点同样标记 `cancelled`。
9. 超时按模块的「超时（秒）」处理，默认 300 秒。

命令由宿主用 shell 执行（Windows 走 `cmd.exe /d /s /c`，macOS / Linux 走系统 shell），工作目录固定为执行文件夹，不再使用模块的 `cwd`。命令模板里用 `@@名称@@` 引用已定义的输入 / 输出 / 参数；输出替换为执行文件夹下的输出文件路径，参数替换为其值。也支持 `@@run_id@@`、`@@node_path@@`、`@@node_dir@@`、`@@input_dir@@`、`@@input_file@@` 等内置引用。路径引用建议在 shell 中加引号。

每个节点执行时还会注入：

| 环境变量 | 内容 |
| --- | --- |
| `AETHER_RUN_ID` / `AETHER_RUN_DIR` | 运行 id 与运行目录 |
| `AETHER_NODE_ID` / `AETHER_NODE_PATH` / `AETHER_NODE_DIR` | 节点 id、路径（`a/b`）与执行文件夹（也是命令的 cwd） |
| `AETHER_EXEC_DIR` | 执行文件夹，同 `AETHER_NODE_DIR` |
| `AETHER_GRAPH_ID` / `AETHER_GRAPH_NAME` | 运行时使用的实验 |
| `AETHER_ENVIRONMENT_ID` / `AETHER_ENVIRONMENT_NAME` | 节点声明的执行环境 |
| `AETHER_EXECUTOR` | 实际执行该节点的执行器 id |
| `AETHER_PORTS` | 节点的输入/输出端口 JSON（`{ inputs, outputs }`） |
| `AETHER_DATASET_URI` / `AETHER_DATASET_FORMAT` | 数据集节点声明的 URI 与格式（仅 `dataset` 节点） |
| `AETHER_INPUT_DIR` | 本节点的 `input/` 目录：按输入端口名存放实际输入（文件/目录输入是复制过来的产物，其他类型是文本文件） |
| `AETHER_INPUT_FILE` | 本节点的 `inputs.json`：上游状态、退出码、stdout 开头文本，以及输入端口到 `input/` 文件的映射 |
| `AETHER_INPUTS` | 输入端口到 `{ type, path, text }` 的 JSON 字符串 |
| `AETHER_PARAMS` | 节点参数 JSON |
| `AETHER_PARAM_<KEY>` | 每个参数一个变量，键名大写、非字母数字换成 `_` |

上游节点的完整 stdout 会写到 `outputs/<节点路径>.out`，本节点的完整输出在 `nodes/<节点路径>/stdout.log` / `stderr.log`。子图模块的参数会作为内层节点的默认参数（内层自己的参数优先）。

## 执行环境与远程调度（预留）

模块带有 `environmentId`，指向 `state.json` 的环境目录。内置环境只有本机：

```json
{ "id": "local", "name": "本机", "executor": "local", "builtin": true }
```

`executor` 是执行后端 id，由宿主内的 [executor.js](executor.js) 解释；资源详情里的「执行环境」就是给未来的调度器看的声明。今天所有环境都解析到本机，提交时会把解析结果固化到运行记录里：

```json
{
  "executor": "local",
  "nodes": [
    { "path": "pipeline/train", "environmentId": "local", "environmentName": "本机", "executor": "local" }
  ]
}
```

**执行器边界**：`LocalExecutor` 实现 `describe / start / cancel / readLog`，`index.js` 只依赖这组方法。

- `start(run, plan)` 返回 `{ done, cancel() }`；执行器负责推进 `run.nodes` 并持久化，宿主持有句柄用于取消与回收。
- `cancel(handle)`、`readLog(run, nodePath, stream)` 供取消与面板日志使用。
- 只有 `describe().available` 的执行器参与环境解析；`/state` 会把环境目录与执行器能力一起返回。

接入服务器调度的目标流程（实验、模块与运行记录的字段不需要再改）：

1. **提交**：把展开后的 plan（节点已带 `environmentId`、参数与模块命令快照）提交给调度器，必要时附上 run 元数据（id、名称）。
2. **放置**：调度器按执行环境选择执行位置，返回每个节点的 placement 与远端 run id。`environmentId` 是两边共享的契约；endpoint、凭据与资源标签由服务器侧持有，本地目录只保存 id 与展示名。
3. **对账**：远端回报节点 `running/succeeded/failed`、退出码与日志位置，宿主镜像到同一份 `run.nodes`。
4. **取消 / 日志**：转发到远端 run id；`readLog` 从远端拉取，或改为跳转外部日志地址。
5. **跨执行器**：上游 stdout 目前通过共享的 `run.dir/outputs` 传递；远程节点需要对象存储或服务器中转，这是调度器侧的数据面问题。

模块库目前仍以本地 `state.json` 为准；提交的 plan 已经带上每个节点的模块快照（命令、参数、端口、执行环境），因此服务器不需要访问本机存储就能决定执行位置。

有意留空、尚未实现的部分：环境目录的增删改与凭据管理、`RemoteExecutor`、服务器端调度协议、跨执行器数据传递、日志流式推送。当前提交只接受存在且执行器可用的环境；写了未来环境名的模块会在提交时明确报错，而不会静默落到本机。

## 数据与工作区

默认工作区是 `$DSH_HOME/storages/aether`；也可以点顶栏工作区路径旁的「更改」指定任意目录。切换后，工作区清单、`state.json`、分类模块目录、实验/子图目录、`runs` 与导入备份都在同一个目录下。

切换规则：
- 目标目录为空：复制当前 `state.json`、`resources`、`experiments`、`subgraphs`、`runs` 后切换；
- 目标目录已有 `state.json`：直接打开该工作区，不覆盖其中数据；
- 有运行中的实验、目标位于当前工作区内部（或包含当前工作区）时拒绝切换。

工作区路径指针保存在固定位置 `$DSH_HOME/storages/aether-workspace.json`，只用于启动时定位工作区；真正的配置清单是工作区内的 `aether.workspace.json`。

### 导入 / 导出

工作区对话框支持 JSON 工作区包（`aether-workspace-*.json`）：

- **导出**包含分类资源目录（`resource.json` / `files` / `versions`）、实验与子图目录、`state.json`；暂不包含 `runs`。
- **导入**会替换当前资源与图；运行记录保持不变，不会被导入包覆盖。
- 导入前会把当前工作区备份到 `<workspace>/.aether-backups/import-<时间>/`，不会静默覆盖。
- 导入包只接受 `resources/**`、`experiments/**`、`subgraphs/**` 路径；兼容旧包的 `modules/**` 并自动迁移。带路径越界/大小/文件数校验；工作区清单随包导入，导入包中的 `runs/**` 会被忽略。

```
<workspace>/
  aether.workspace.json   # 工作区清单：格式/版本/目录布局/创建时间
  state.json              # 模块索引、图定义、执行环境目录  resources/
    modules/<module>/     # 模块资源
    subgraphs/<module>/   # 子图资源
    datasets/<module>/    # 数据集资源
      resource.json       # 必备描述文件
      files/              # 资源提交的文件或目录
      versions/vN.json    # 历史版本快照（最多 20）
  experiments/<graph>/
    experiment.json       # 可独立运行的实验定义
  subgraphs/<graph>/
    subgraph.json         # 被图模块引用的子图定义
  runs/<run-id>/
    run.json              # 运行、执行器、布局方向、展开后的连线、逐节点 placement 与状态
    nodes/<node>/         # stdout.log / stderr.log / inputs.json
    outputs/<node>.out    # 供下游读取的 stdout
  .aether-backups/        # 导入工作区前的自动备份
```

面板顶部显示工作区路径，可直接复制；「打开目录」在系统文件管理器里打开它。删除实例会删掉对应的 `runs/<id>` 目录。旧版 `state.json` 加载时会自动迁移：v1 → v2 补执行环境，v2 → v3 给模块补默认端口（`input` / `output`）、给旧连线补默认端口，v3 → v4 记录布局方向（默认上下）并清空旧横向坐标，v4 → v5 给模块补版本号与版本历史，v5 → v6 给模块补必填输入端口列表，v6 → v7 将模块/实验/子图迁移到分类目录，v7 → v8 将 `modules` 目录重命名为 `resources`、`module.json` 重命名为 `resource.json`，v8 → v9 为输入/输出/参数补类型并把命令模板统一为 `@@名称@@`，v9 → v10 把模块 / 数据集 / 子图 / 实验的 id 换成全局唯一的 UUID（迁移前备份到 `.aether-backups`），同时把旧的运行记录 id 换成 UUID 并重命名 `runs/<id>` 目录，不需要手工处理。

首次加载（还没有 `state.json`）时会写入一组示例数据：4 个命令模块（准备数据、训练模型、评估结果、生成报告；带 `dataset` / `model` / `metrics` 端口）、1 个子图模块（演示流水线）、1 个数据集模块（`datasets/demo.jsonl`）和 2 个实验（`demo-pipeline`、`nightly-experiment`），画布坐标也已就位。可以直接运行「夜间实验」看一次完整的子图执行，也可以全部删掉从零开始。

## HTTP 接口

面板通过 `/aether-api` 访问宿主：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/state` | 模块、实验摘要（含 `isSubgraph` / `usedBy`）、环境和执行器能力、运行摘要、工作区 |
| GET | `/graphs?id=` | 实验详情与展开后的执行计划（不带 id 时返回摘要列表） |
| POST | `/graphs` | 新建 / 更新实验（`{ graph }`，节点含 `x/y`，连线含 `fromPort/toPort`） |
| POST | `/graphs/validate` | 预检实验，返回 `errors[]` 与计划 |
| DELETE | `/graphs?id=` | 删除实验（被子图模块引用时拒绝） |
| POST | `/modules` | 新建资源（`{ create: true, module }`）；资源创建后不可修改，更新请求返回 409 |
| POST | `/modules/assets` | 提交模块文件 / 目录（`{ kind, name, files: [{ path, dataBase64 }] }`），返回 `assetId / assetPath` 等字段 |
| DELETE | `/modules?id=` | 删除模块（被实验使用时拒绝） |
| GET | `/experiments?id=` | 运行详情与节点（不带 id 时返回摘要列表） |
| POST | `/experiments` | 运行实验（`{ graphId, graph?, name?, concurrency? }`）；带 `graph` 时按草稿运行且不保存，未保存的新实验也可以提交；被模块引用的子图会被拒绝 |
| POST | `/experiments/cancel` | 取消运行（`{ id }`） |
| POST | `/experiments/rerun` | 按当前实验重跑（`{ id }`） |
| POST | `/experiments/open` | 在文件管理器里打开该运行目录 |
| DELETE | `/experiments?id=` | 删除运行（运行中拒绝） |
| GET | `/experiments/logs?run=&node=&stream=out\|err` | 节点日志 |
| GET | `/experiments/artifact?run=&node=&port=&file=` | 查看端口输出：文件内容或目录列表；未映射时回退 stdout |
| GET | `/experiments/artifact/download?run=&node=&port=&file=` | 下载端口输出文件；目录打包为 ZIP |
| GET | `/experiments/download?run=&node=&port=` | 兼容接口：下载节点 stdout |
| POST | `/workspace` | 切换工作区（`{ path }`）；空目录会迁移当前数据，已有 `state.json` 则直接打开 |
| GET | `/workspace/export` | 导出工作区 JSON 包（暂不包含运行记录） |
| POST | `/workspace/import` | 导入工作区包（`{ bundle }`），导入前自动备份；不导入运行记录 |
| POST | `/workspace/open` | 打开 Aether 工作区 |

所有接口返回 `{ ok: true, ... }` 或 `{ ok: false, error }`。写接口带 2MB 请求体上限。

## 实现说明

代码分层与客户端构建方式见 [ARCHITECTURE.md](ARCHITECTURE.md)。

- `index.js`：宿主插件。注册 `/aether-api` 路由；保存模块 / 实验 / 环境目录；提交时解析环境 → 执行器；退出时取消仍在跑的句柄。
- `constants.js` / `seed.js` / `http.js`：数据版本与上限、首次启动示例数据、HTTP 基础设施。
- `dag.js`：纯函数核心——参数 / 模块 / 端口 / 实验 / 环境的归一化、校验、拓扑分层、子图展开、图引用环检测、旧连线端口补全。
- `executor.js`：执行后端边界。`resolvePlacements` 把节点的执行环境解析成执行器；`LocalExecutor` 是本机实现，`start / cancel / readLog` 之外的存储与 API 不感知执行位置。
- `client.js`：构建产物，唯一被 DSH 加载的客户端文件。源码在 `client/src/` 按职责拆成文案、样式、工具、小部件、运行视图、图列表、画布、实验编辑器、模块库、主面板与注册片段；修改源码后运行 `npm run build`。
- `test/dag.test.mjs`：图核心单测（拓扑、环、子图展开、嵌套子图、参数继承、环境与端口校验、坐标与布局方向、旧连线迁移）。
- `test/executor.test.mjs`：环境解析与执行器描述。
- `test/host.test.mjs`：用假 `ctx` 起真实 HTTP 服务，覆盖种子数据、CRUD 保护、环拒绝、子图不可单独运行、端口与坐标往返、必填输入校验、数据集节点、模块版本、模块文件上传与无命令执行、文件/目录输出与 ZIP 下载、子图执行、工作区切换/迁移、失败传播、取消与 placement 快照。
- `test/client-build.test.mjs`：确保 `client.js` 与 `client/src/` 片段一致。

```bash
npm run build
npm test
```

宿主侧没有注册 agent 工具，操作入口只有面板与 HTTP 接口；如果后续要让 agent 提交实验，建议复用同一套 `startExperiment` / `saveGraph` 逻辑再注册 `tools.register`。

## 已知边界

- 模块命令在宿主进程的权限下执行，没有额外的沙箱；命令内容应视为用户自己的脚本。
- 目前只有本机执行器，所有节点都在本机运行；远程执行器与服务器调度尚未实现（见「执行环境与远程调度」）。
- 端口目前用于画布与提交契约，执行时数据仍按节点依赖通过 `inputs.json` / `outputs` 传递；尚未做“端口级数据路由”（例如同一节点不同输出分别喂给不同下游）。
- 模块文件通过浏览器上传，受浏览器选择能力限制；单次提交最多 500 个文件、总计 20MB（界面按 12MB 预检），不支持直接引用工作区外的绝对路径。
- 数据集节点只传递 URI 指针，不复制或校验数据本身；数据集内容由下游命令自行读取。
- 子图展开是静态内联；暂不支持「按条件跳过」「循环」「失败重试」等控制流。
- 运行记录最多在列表里显示 200 条；更早的记录仍留在磁盘上，可通过运行目录访问。
