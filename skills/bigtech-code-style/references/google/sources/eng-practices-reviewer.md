# How to do a code review

The pages in this section contain recommendations on the best way to do code
reviews, based on long experience. All together they represent one complete
document, broken up into many separate sections. You don’t have to read them
all, but many people have found it very helpful to themselves and their team to
read the entire set.

- [The Standard of Code Review](/eng-practices/review/reviewer/standard.html)
- [What to Look For In a Code Review](/eng-practices/review/reviewer/looking-for.html)
- [Navigating a CL in Review](/eng-practices/review/reviewer/navigate.html)
- [Speed of Code Reviews](/eng-practices/review/reviewer/speed.html)
- [How to Write Code Review Comments](/eng-practices/review/reviewer/comments.html)
- [Handling Pushback in Code Reviews](/eng-practices/review/reviewer/pushback.html)

See also the [CL Author’s Guide](/eng-practices/review/developer/), which gives detailed
guidance to developers whose CLs are undergoing review.
