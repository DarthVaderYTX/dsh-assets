# One Pager模板

复制本模板即可动笔，配合 [../README.md](../README.md) 使用：先读整体要求，再取模板，最后按 README 的逐节要求与交付检查核对。

三部分：空白模板 → 填写示例（示意粒度，示例值均为虚构）→ 真实示例（可核查链接，没有就写"暂无"，不要编造）。

## 一、空白模板

```markdown
# [提案名称：一句话说清要做什么]

## 1. 头部信息与结论
- 状态 / 版本 / 更新日期：[已确认信息；未知写待确认]
- 提案方 / 决策方：[已确认身份；未知写待确认]
- 建议与请求：[建议采取什么行动、请决定什么、关键依据]

## 2. 问题与时机
- 问题：[谁受到什么影响；关键证据]
- 为什么现在：[时间窗口 / 不行动代价及依据]

## 3. 提案与范围
- 做什么：[核心行动与工作边界]
- 不做什么：[最易混淆的非范围]
- 为什么选它：[相较主要替代路径的关键取舍]

## 4. 收益与判断依据
- 受益对象与结果：[对象、预期变化]
- 指标 / 基线 / 预期 / 依据：[事实、目标或估算分别标明]
- 核验方式：[如何判断有效；缺失数据及确认路径]

## 5. 投入与执行路径
- 投入：[人力、预算、持续成本或机会成本；已确认 / 待确认]
- 路径：[关键阶段、结果与依赖；时间状态]
- 投入边界：[批准范围或上限；已确认 / 待确认]

## 6. 决策请求与下一步
- 请决定：[批准 / 否决 / 选择 / 允许验证的具体事项]
- 决策边界：[授权范围、条件及所需决策时间的依据]
- 若批准 / 若不批准：[下一步行动、责任方与时间状态]

## 7. 关键风险与应对
- 风险：[触发条件与决策影响]
- 应对：[控制措施、停止条件或替代路径]
- 未决项：[影响本次决定的缺口及确认路径]

## 8. 附件与来源索引
- 关键来源：[链接、用途、时间 / 版本]
- 详细附件：[链接及所支持的正文判断；无附件时说明]
```

## 二、填写示例（虚构，仅示意粒度）

```markdown
# 工单自动分派试点：先在一个业务线跑四周

## 1. 头部信息与结论
- 状态 / 版本 / 更新日期：待决策 · v1 · 2026-11-03
- 提案方 / 决策方：客户支持部 / 支持负责人（待确认）
- 建议与请求：建议批准 2 人周 + 1 名标注兼职，在退款工单线试点四周；请确认试点范围与停止条件。

## 2. 问题与时机
- 问题：退款工单平均首次分派耗时 42 分钟，错派率 18%（S1，2026-09 至 10 工单数据）。
- 为什么现在：Q4 工单量预计增长 30%，人工分派先到瓶颈；本季度有标注人力空档。

## 3. 提案与范围
- 做什么：用规则 + 小模型对退款工单自动打标并分派，人工只处理低置信度。
- 不做什么：不覆盖咨询、投诉类工单；不做全自动闭环回复。
- 为什么选它：相较增加排班人力，单位成本更低且可回退；相较外采 SaaS，数据不出内网。

## 4. 收益与判断依据
- 受益对象与结果：退款工单处理人，减少手工分派与错派返工。
- 指标 / 基线 / 预期 / 依据：首次分派耗时 42 min（实测）→ 目标 ≤ 15 min（估算，基于自动分派占比 70% 假设）；错派率 18% → ≤ 10%（目标）。
- 核验方式：试点期比对同业务线同期人工分派数据；若标注人力不足则先只测耗时。

## 5. 投入与执行路径
- 投入：2 人周研发 + 0.5 人力标注（4 周）；无新增采购。
- 路径：规则基线 1 周 → 小模型接入 1 周 → 四周试点 → 复盘决策；具体排期待确认。
- 投入边界：本次只批准试点，不含全量推广与后续维护排期。

## 6. 决策请求与下一步
- 请决定：是否批准试点，以及试点覆盖的工单范围。
- 决策边界：试点期内错派率高于 18% 即暂停，不进入推广评估。
- 若批准 / 若不批准：批准则下周启动并每周同步；不批准则维持人工分派，记录待评估。

## 7. 关键风险与应对
- 风险：模型对促销期特殊规则不熟，错派集中在月末。
- 应对：月末降级为人工分派；保留一键改派与回溯。
- 未决项：标注人力能否到位（影响四周试点能否跑完）。

## 8. 附件与来源索引
- 关键来源：S1 工单数据导出（2026-09-01 至 10-31）
- 详细附件：分派规则草案、试点观测指标表；暂无外部材料。
```
