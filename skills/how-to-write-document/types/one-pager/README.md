# One Pager 写作规范

## 一、整体要求与约束

- **用途（必须）**：让决策者快速判断一个明确提案：批准、否决、选择方案或补齐证据。开头给建议和决策请求，正文保留足以判断价值、代价和风险的信息，不把一页纸写成缩小字号的完整报告。
- **读者（必须）**：面向能作出相关决策的负责人及必要协作方。使用他们能理解的业务语言；不能假定其了解项目历史或技术术语。决策权限未知时标待确认，不擅自指定拍板人。
- **证据（必须）**：问题、时机和收益判断给关键来源与口径；区分事实、估算、目标和假设。估算说明依据、主要假设与不确定性，详细计算放附件。不得把预期效果写成已实现收益，不使用没有依据的精确数字。
- **篇幅与取舍（必须）**：正式输出正文为一页，允许详细附件。Markdown 无分页时写简短正文，不声称已验证页数；转为正式排版后检查正文一页。通过删重复、压缩表达和移出细节实现一页，不能用极小字号、删关键风险或固定字数替代内容质量。附件不限于一页，但决策所需核心信息必须留在正文。
- **风格（必须）**：直接压缩，先结论后依据，短句、动词明确。每句话服务于问题、证据、取舍或请求；不写团队历史、感谢、口号和无依据的“显著、巨大、领先”。**建议**用短列表与窄表格，避免排版拥挤。
- **缺失信息（必须）**：未知收益基线、投入、负责人、日期、决策权限或外部承诺标“待确认”，说明其对决策的影响和确认路径；不能为了让提案显得完整而编数或承诺。关键证据不足时，可请求批准验证或限定试点，但验证范围、资源与停止条件仍需明确；未知部分继续待确认。
- **规范强度**：“必须”为底线；“建议”可按场景调整；“条件适用”须说明是否适用，不适用项用短句交代。详细产品规格可链接 [PRD](../prd/README.md)，工程设计可链接 [技术方案 / 设计文档](../technical-design/README.md)，此处不引入它们的写作约束。

## 二、整体结构与模板

章节按下列顺序组织，顺序固定；不适用的小节说明原因后省略，不删除整段证据链。

1. 头部信息与结论
2. 问题与时机
3. 提案与范围
4. 收益与判断依据
5. 投入与执行路径
6. 决策请求与下一步
7. 关键风险与应对
8. 附件与来源索引

完整可复制模板见 [templates/one-pager.md](templates/one-pager.md)，内含空白模板、填写示例、真实示例链接。写作时先取模板，再回到本文「三、各部分写作要求」逐节核对；模板与本文小节一一对应。

## 三、各部分写作要求

### 1. 头部信息与结论

- **目的**：让读者立即识别提案状态和要作的决定。
- **必须写什么**：标题、状态/版本/更新日期、提案方与决策方、建议行动、决策请求和最关键依据。未知身份或日期待确认，未获批准不能显示为已决定。
- **表达要求**：头部紧凑；结论用短句，可先写“建议[行动]，请确认[范围]，依据是[关键证据]”。这是占位表达，不是实际承诺；详细授权范围在第 6 节展开，不重复整段。
- **如何检查**：只读开头能说出提案、建议和所需决定；关键依据可在后文核验。
- **常见错误**：开头只有背景；编造资源和时间让结论显得具体；用“请支持”代替决策请求。

### 2. 问题与时机

- **目的**：说明为什么值得处理，以及为什么此时作决定。
- **必须写什么**：受影响对象、核心问题、关键证据、行动窗口或不行动代价；不存在确定窗口时直说，不制造紧迫感。
- **表达要求**：只保留改变决策的事实；时间窗口和外部承诺附依据，过长背景移到附件。
- **如何检查**：证据支持问题规模与时机；读者能区分事实和推断；不行动代价不是未经验证的恐吓。
- **常见错误**：团队发展史；无来源的“竞争压力”；把期望上线日期写成客户已承诺期限。

### 3. 提案与范围

- **目的**：界定批准的对象和最关键取舍。
- **必须写什么**：核心行动、覆盖对象/阶段、非范围、相对主要替代路径的选择依据。**条件适用**：维持现状或小规模验证是可行选择时，简述其与推荐提案的差别。
- **表达要求**：用非专业读者能理解的动作与结果，不展开接口或实现细节；避免堆多个独立提案。
- **如何检查**：读者能界定做什么和不做什么；范围与投入、收益一致；推荐理由不是自我评价。
- **常见错误**：只有愿景无行动；将所有后续能力默认纳入；比较结论没有代价依据。

### 4. 收益与判断依据

- **目的**：让决策者判断回报是否可信、是否值得投入。
- **必须写什么**：受益对象、结果、关键指标/基线/预期及证据、核验方式；以下收益要素按适用性写清，不凑数字。
- **表达要求**：优先保留最能改变决定的收益，计算移附件；标清实测、目标、估算或定性判断。
- **如何检查**：收益与提案范围有关，来源可追溯，缺口和不确定性未隐藏。
- **常见错误**：把目标写成承诺；收益很精确但没有基线；把所有间接影响都计入回报。

#### 收益口径与可信度

**必须**说明谁受益、改善什么、相对什么现状、如何测量；涉及数量时写单位、窗口和数据依据。无基线写“基线待确认”及获取路径；尚不能量化的价值可给定性证据和验证方法，不能强造百分比。估算给主要假设，区分一次性与持续收益，避免重复计算。检查基线与预期口径相同、收益时点合理；无证据时应请求验证，而非承诺回报。

### 5. 投入与执行路径

- **目的**：说明需要付出什么，以及提案如何转成行动。
- **必须写什么**：主要资源、关键阶段与阶段结果、依赖、投入边界及确认状态；细节放附件，但正文不能隐去主要持续成本。
- **表达要求**：简短列出阶段动作，阶段数量按实际需要，不强凑固定步数；已承诺计划与建议安排分开。
- **如何检查**：投入覆盖提案范围，路径与依赖一致，日期和资源并非臆测。
- **常见错误**：只算开发不算运维或业务协作；路径只有口号；估算被写成团队承诺。

#### 投入、边界与机会成本

**必须**说明已知人力角色/工作量、预算或资源消耗、一次性与持续成本中适用项及估算依据；说明此次申请的范围或上限。**条件适用**：挤占已承诺工作时写机会成本，外部依赖影响资源时写确认状态。未知成本或上限写待确认，并指出是否阻止投入决策。检查收益与投入单位/周期可比较、依赖没有被当成免费资源；避免擅自填负责人、工期或预算。

### 6. 决策请求与下一步

- **目的**：把“理解提案”转成可执行的明确决定。
- **必须写什么**：具体决定事项、授权范围与条件、决策时限依据、批准或不批准后的行动及责任/时间状态；没有明确时限则不编截止日。
- **表达要求**：直接请求动词，明确批准对象；引用第 5 节投入边界，不重复整张投入表。不能以“同步一下”掩盖要资源或要授权。
- **如何检查**：批准后实施方知道允许做什么，未批准也有清楚后果或替代路径；请求不越过决策方已知权限。
- **常见错误**：只说“请拍板”；请求多个无关决定；把批准验证等同于批准全面上线。

#### 决策对象、条件与后续动作

**必须**将请求明确到方案、资源范围、试点或验证授权；存在前置条件时写清“满足哪些条件才执行”。**条件适用**：证据不足时可以申请限定验证，说明要回答的问题、投入边界、结果判断与停止条件，未知部分待确认。下一步写动作与产物，确认过的责任方/日期才可列作承诺。检查本次决定和后续扩张是否分开；避免用“若批准立即完成”制造无依据承诺。

### 7. 关键风险与应对

- **目的**：让决策者看到可能推翻收益或扩大代价的条件。
- **必须写什么**：影响本次决定的主要风险、触发条件、后果、应对、停止或替代条件，以及关键未决项的影响和确认路径。
- **表达要求**：正文只保留关键风险，详细清单放附件；风险与措施一一对应，不填写无依据的概率数字。
- **如何检查**：读者知道最可能改变决定的事项，措施确实降低对应风险，未决项未被结论当作已解决。
- **常见错误**：只写“可控”；措施是“加强沟通”；隐藏大额持续成本或不可逆影响。

#### 风险、停止条件与未决项

**必须**写“什么条件发生—影响什么—采取什么动作”；风险涉及不可逆动作时说明必要的批准前置条件。**条件适用**：试点、资源消耗或收益验证可能失控时，写可观测停止条件与后续选择；阈值未知则待确认，不虚构。区分可接受风险与阻塞决定的缺口。检查措施能执行、未知项的确认结果会如何改变请求；避免把没有验证的“低风险”当事实。

### 8. 附件与来源索引

- **目的**：让读者可追查依据、深入细节，同时保持正文一页。
- **必须写什么**：关键来源链接、用途和时间/版本；有详细附件时说明支持哪项判断，无附件时明确说明。附件可以承接计算、研究、实施细节与完整风险表。
- **表达要求**：正文索引简短，附件另行呈现；来源可与正文引用合并但此节保留索引。若给具体示例，必须标“虚构格式示例”，不能当作事实证据。
- **如何检查**：附件能支持正文结论、版本一致、链接正确；不打开附件仍能判断提案、投入、请求和关键风险。
- **常见错误**：一页只剩链接；收益依据全部藏附件；附件引入正文未披露的重大成本。

## 四、交付前检查

- [ ] 编号部分与模板一致，头部信息完整或明确待确认；开头直接给建议、请求与关键依据。
- [ ] 问题、时机、提案、收益、投入、决定与风险构成一条判断链，范围一致。
- [ ] 实测、估算、目标和假设分开；没有编造基线、效果、资源、负责人、日期或承诺。
- [ ] 决策对象和授权边界具体，下一步有动作与产物；关键未知项说明决策影响。
- [ ] 正文包含主要代价、关键风险和停止条件等适用信息，附件没有藏重大取舍。
- [ ] 正式排版正文确为一页且正常可读；Markdown 无分页时使用简短正文，未声称已验证页数。
- [ ] 附件可详细展开，但正文无需打开附件也能理解并作出决定。
- [ ] Markdown 围栏成对、表格可读、来源与交叉链接有效；删除重复铺垫和无依据形容词。
